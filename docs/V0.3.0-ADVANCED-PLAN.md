### 1.3 Version-convergence rule (app ↔ NuGet, decided 2026-10-05, continued)

- Maintainer wants NuGet package version to meet GitHub app version at joint `0.5.0`.
- Standing policy: new template surface = template MINOR (precedent: list-details + datagrid `0.3.x → 0.4.0`). v0.3.0 ships new surface (`devtem-contentgrid`), which would normally mean templates `0.5.0` now.
- Convergence override for this cycle: **small PATCH increments per version** until both meet at `0.5.0`:

| App (GitHub `v*`) | Templates (NuGet `templates-v*`) | Note |
| --- | --- | --- |
| `0.2.0-beta` (shipped) | `0.4.2` (shipped, convergence PATCH) | Baseline |
| **`0.3.0-beta` (this plan)** | **`0.4.3`** | ContentGrid item template ships but version stays PATCH by convergence decision, not by policy |
| `0.4.0-beta` | `0.4.4` | Planned PATCH |
| `0.5.0-beta` | `0.5.0` | **Convergence: both `0.5.0`, policy resumes from here** |

- Record the deviation in `docs/DECISIONS.md` at commit time (Appendix): the
  `0.4.3` number is a deliberate convergence PATCH, not a "content-only" claim.
- Mechanism reminder: CI passes `-p:Version` from `templates-v*` tags; the
  `Packaging/DevTem.Templates` csproj fallback (`0.3.5`) is never edited.
