### 1.3 Version note (joint `0.7.0` meet — earned, not assumed)

- Maintainer rule from v0.6.0: **app and templates share the number** (`0.7.0-beta` / `templates-v0.7.0` → NuGet `0.7.0`). The meet holds automatically *if* v0.7.0 ships new template surface; standing policy (ROADMAP §7.4) is explicit: template MINOR for new symbols/values, PATCH for content.
- Honest tension, stated up front: the v0.7.0 box as written (a11y pass, state gallery, perf re-proof) is product behavior + docs + tests — **content, not surface**. A11y must be default-on, never a flag (flag discipline P3-4/C6: a boolean without a consumer is declined — an `--a11y` opt-in would be exactly that). So the meet is a *target*, not a premise.
- Mechanism (unchanged): `bump-version.ps1 -Version 0.7.0-beta` renumbers the app quartet + CITATION + CHANGELOG stub only; the NuGet version flows from the `templates-v*` tag via CI `-p:Version`; the packaging-csproj `<Version>` fallback is never edited.
- Fallback (honest, not silent — same pattern as v0.6.0 §1.3): if no new symbol/value earns its way in during WB-02…WB-04 evaluation, v0.7.0 ships content-only → templates tag becomes **`0.6.2` PATCH** per policy, and the matched-number rule defers one more cycle via an explicit DECISIONS entry. The plan targets the meet; it does not fake it. (Genuine surface candidates, if any, are named at evaluation time — not invented here.)

### WB-02 — Live a11y pass: Narrator run + keyboard map + AutomationProperties audit

- **Goal:** the first *run*, not the first *claim* — intents become notes, notes become fixes.
- **Files:** audit table (new doc or DECISIONS-adjacent section — repo-only either way):
  every interactive control → `AutomationProperties.Name` / headings structure / live-region
  (`NotificationService` host = Polite, validation/update errors = Assertive, applog tail =
  deliberately silent) → verdict; `docs/` keyboard-map (Tab order, dialog focus-trap,
  wizard PipsPager keyboard path, `KeyboardShortcuts` reservations mapped); product fixes in
  `Services/` + `Controls/` + `Pages/` (+ template mirror, same commit).
- **Method (run-first):**
  1. **Narrator run:** protocol recorded (build, Narrator version, voice/verbosity) + per-surface notes (Home, Settings, wizard, update popup, tray menu, toasts, dialogs). Anything needing a human ear is marked `manual` — never auto-filled.
  2. **Keyboard map:** full Tab walk on a quiet desktop, focus-trap check per dialog, documented order; fixes where focus is lost or trapped wrongly.
  3. **AutomationProperties audit:** static sweep first (missing names, heading levels), then Narrator confirms; fixes land as XAML/code diffs with headless-testable assertions where possible (new a11y unit tests — e.g. name-presence, live-region settings — alongside `DialogButtonLanguageTests`-class coverage).
- **Constraints:** no control adoption (v0.8.0 owns controls — an a11y-motivated control swap still waits for v0.8.0 evaluation; fix hand-rolled, document the candidate); no behavior change beyond a11y (states → WB-04, perf → WB-05); PII-redacted notes.
- **Acceptance:** audit table complete with verdicts; Narrator notes filed in DECISIONS; keyboard-map doc exists and matches the build; new a11y tests green; smoke suite extended with the scriptable subset (FlaUI where the rig allows, manual-marked where it does not).
