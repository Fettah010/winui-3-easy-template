### 1.3 Version-convergence rule (app ↔ NuGet, decided 2026-10-05)

- The maintainer wants the **NuGet package version to eventually match the GitHub app
  version**, both at `v0.5.0`.
- Standing policy says new template surface = template MINOR bump (precedent:
  list-details + datagrid took templates `0.3.x → 0.4.0`). v0.2.0 ships new
  surface (`devtem-tabview`), which would normally mean templates `0.5.0` now.
- Convergence override for this cycle: **small PATCH increments per version**
  until both meet at `0.5.0`:

| App (GitHub `v*`) | Templates (NuGet `templates-v*`) | Note |
| --- | --- | --- |
| `0.1.0-beta` (shipped) | `0.4.1` (shipped, content PATCH) | Baseline |
| **`0.2.0-beta` (this plan)** | **`0.4.2`** | TabView item template ships but version stays PATCH by convergence decision, not by policy |
| `0.3.0-beta` | `0.4.3` | Planned PATCH |
| `0.4.0-beta` | `0.4.4` | Planned PATCH |
| `0.5.0-beta` | `0.5.0` | **Convergence: both `0.5.0`, policy resumes from here** |

- Record the deviation in `docs/DECISIONS.md` at commit time (Appendix): the
  `0.4.2` number is a deliberate convergence PATCH, not a "content-only" claim.
- Mechanism reminder: CI passes `-p:Version` from `templates-v*` tags; the
  `Packaging/DevTem.Templates` csproj fallback (`0.3.5`) is never edited.
